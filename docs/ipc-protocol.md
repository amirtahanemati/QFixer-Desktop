# پروتکل ارتباطی نسخه ۲ بین هسته Rust و موتور Python

## ۱. ساختار استاندارد فریم پیام
تمام ارتباطات از طریق استاندارد ورودی/خروجی استاندارد (`stdin` / `stdout`) و با فرمت خطوط جیسون (JSON Lines) بدون بافر با انکودینگ UTF-8 صورت می‌پذیرد.

هر پیام ارسالی یا دریافتی ساختار زیر را رعایت می‌کند:

```json
{
  "protocol_version": "2.0.0",
  "message_type": "process_image",
  "request_id": "req-98f7e2a1",
  "payload": {}
}
```

## ۲. انواع پیام‌های معتبر

### ۲.۱. درخواست‌ها از Rust به Python
1. `initialize`: مقداردهی اولیه موتور، بررسی دسترسی به سخت‌افزار (CPU/GPU) و آماده‌سازی رجیستری.
2. `health_check`: پایش وضعیت زنده بودن Worker (ارسال دوره‌ای `ping` و دریافت `pong`).
3. `analyze_image`: تحلیل ساختار، محتوا، متادیتای رنگ و شناسایی نواحی فرمول/متن/شکل.
4. `process_image`: اجرای پایپ‌لاین فیلترها به همراه ماسک‌های حفاظتی روی فایل ورودی.
5. `preview`: تولید یک پیش‌نمایش سبک (Low-res یا Tiled) برای پاسخ آنی به اسلایدرها در UI.
6. `export`: ذخیره تصویر نهایی با فرمت درخواستی (PNG / JPEG / TIFF) و تنظیمات کیفیت.
7. `cancel`: درخواست لغو یک پردازش طولانی‌مدت بر اساس `request_id`.

### ۲.۲. پاسخ‌ها از Python به Rust
1. `progress`: گزارش درصد پیشرفت پردازش (`percent`: 0-100، `stage`: نام مرحله پردازشی).
2. `result`: خروجی پردازش، مسیر فایل خروجی موقت، متادیتای آماری و برچسب‌های کیفی.
3. `error`: پیام ساختاریافته خطا شامل کد خطا، پیام کاربرپسند و جزئیات تکنیکال.
4. `health_status`: گزارش وضعیت سلامت و میزان مصرف RAM و VRAM.

## ۳. انتقال داده‌های تصویری حجیم
- **ممنوعیت Base64:** برای جلوگیری از مصرف حافظه و افت شدید نرخ فریم در رشته‌های طویل جیسون، از رشته‌های Base64 در فریم‌های داده‌ای بزرگ استفاده نمی‌شود.
- **فایل‌های حافظه موقت (Managed Scratch Files):** تصاویر ورودی و خروجی‌های موقت در پوشه ایزوله `app_cache/temp_frames` ذخیره شده و صرفاً مسیرهای اعتبارسنجی‌شده بین پردازه‌ها منتقل می‌شوند.
